# Prior art and design notes

Searched 2026-11-20. The question was whether an existing tool already does
"drag the spacing of figure components, then write the numbers back".

## Closest implementations

1. **mpltweak** (GitHub `shdbl/mpltweak`, Chinese description: "像在 PPT 里调多图排版一样调 matplotlib，然后把参数写回你的代码")
   - Interactive layout editor for matplotlib figures and subplots.
   - Drag margins and gaps like arranging PowerPoint slides.
   - Writes the resulting numbers back into the user's code.
   - This is the same idea as the requested plugin, but it is a standalone
     matplotlib editor, not an editor for a hand-rolled canvas that renders
     publication plates. Our plates are drawn with a custom `Cv` class on fixed
     canvas units, so mpltweak cannot see their tokens.
2. **FigureForge** (GitHub `nogula/FigureForge`)
   - GUI over a pickled matplotlib figure: labels, fonts, marker sizes, colors.
   - It edits a live figure object, not source-code spacing constants, and does
     not write numbers back into the script that generated the figure.
3. **Matplotlib's own tooling**: `subplots_adjust` / `tight_layout` / constrained
   layout are programmatic, not interactive. The interactive docs cover pan/zoom
   and event hooks, not a spacing editor.
4. **Inkscape / Illustrator / Figma**: real spatial editors, but they edit the
   exported artwork; they cannot regenerate the plate or keep the geometry rules
   (panel width proportional to measured layers).

## What the requested plugin has to do here

Our figures are generated by `experiment/figures/make_family_grids.py`
(Figure 1) and `experiment/figures/make_readme_figs_svg.py` (Figure 2). The
spacing lives in named tokens on a 4-unit grid (`PH`, `LENS_GAP`, `CELLGAP`,
`MGAP`, `TITLE_GAP`, `HEAD_GAP`, `LABH`, `LABEL_GAP`, `ROW_GAP`, `TICKROW`,
`MX`, `PAD`, `LEGEND_GAP`, `TAILPAD`, `FGAP`, `ROW_FAM_GAP`). A useful editor
therefore needs to:

1. read the tokens from the source file (not from a screenshot),
2. render a preview after a change,
3. report the real margins measured from the rendered PNG (the plate is cropped
   to content + `PAD`, so nominal `MX` is not the visible margin),
4. write the new token values back into the source, and
5. expose the same operation to the agent and to the GUI so the two never drift.

## Chosen architecture

- **Host plugin** owns the file patching, the Python render, and the PNG margin
  audit. It exposes three tools (`fig_spacing_read`, `fig_spacing_apply`,
  `fig_spacing_audit`) and a loopback HTTP service on `127.0.0.1` with CORS.
- **Client plugin** (next step) registers a right-sidebar tab with sliders for
  the tokens, calls the loopback service, and shows the rendered PNG. Using a
  loopback service avoids a generated Typert Remote contribution for a
  developer-only tool, and keeps the GUI usable when the agent is idle.

## Deliberate limits

- Editing tokens by hand still works; the plugin only adds a faster loop.
- The service binds to `127.0.0.1` only and accepts no secrets.
- It renders the same commands the manuscript pipeline uses, so a slider change
  is exactly a source change plus a re-render.
